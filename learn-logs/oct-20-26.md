## oct 20, 2026

#### the goal  
deploying an ec2 with a basic nginx app, which has a private sg to control inbound/outbound traffic.
alongside 2 s3 buckets - one the ec2 can access (through iam entities) and one that is forbidden. 

#### related resources 
- ec2
- iam-role-and-policy: deploys the iam role, policy, and outputs the instance_profile for the ec2 access
- s3-bucket

#### what went wrong?

at first the policy profile didn't attach to the ec2, added a few troubleshooting outputs and depends_on. 

when applied, the vm had an instance profile attached but in the aws ui and vm itself the space was empty.

eventually, turned out that the aws ui was on one region and the code was on another, which means the dashboard was giving information on a different pool. 

#### what did i learn (from the flow of the project, not the module building)
- troubleshooting in aws ui and in the ec2 connect panel 
- troubleshooting in terraform cli 
- aws regions and deploying resources in multiple regions 
  - some aws objects are created globally, like iam entities, and some are only per region, like ec2 
- `aws_vpc_security_group_ingress_rule` vs `aws_security_group`
  - define the empty security group `aws_security_group`
  - later on, use `aws_vpc_security_group_ingress_rule` or `aws_vpc_security_group_egress_rule` to define more specific single rules in the sg (inbound/outbound traffic)
