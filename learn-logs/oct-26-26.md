#### what went wrong?
1. i moved the ec2 instance into the private subnet and connected it to an application load balancer so clients from the outside could reach it, but the target (in the lb's target group) showed as unhealthy:
  - i wanted to connect to the server to check whether the httpd daemon was even running on the correct port, but since it was in a closed network, i used SSM instead of ssh, and had to add another IAM policy (`AmazonSSMManagedInstanceCore`) to the ec2 module 
  - then discovered an instance can only have one instance profile, so i had to create a combined role (ssm + the bucket policy) and attach its profile to the ec2 instance 
  - once ssm worked, it showed that the server itself was fine (selinux permissive, no firewalld or similar, `ss` showed httpd listening on the right port)
  - **root cause:** the instance only had the ec2 module's own sg, which allowed port 22 only. the alb health checks (port 80) come from the alb's security group (`alb_sg`), and only `app_sg` from the networking module allows port 80 from `alb_sg`. so the fix was to pass both sgs explicitly to the ec2 instance (`vpc_security_group_ids`), after which the target turned healthy

#### what did i learn (from the flow of the project, not the module building)
- how to use the `terraform test` command 
- difference between public and private subnets - network traffic architectures below 
- an alb needs at least 2 public subnets in 2 different availability zones
- an instance in a private subnet has no route to the internet by itself - outbound traffic (like `dnf install httpd` in the user_data, or reaching ssm) goes through a NAT gateway that sits in a public subnet
- security groups can use another security group as the source (`source_security_group_id`) instead of a cidr block - `app_sg` only accepts port 80 from `alb_sg`
- an instance can have several security groups, and the allowed traffic is the union of all their rules
- security groups are stateful - the response to an allowed inbound request is allowed back out automatically, no matching outbound rule needed
- ssm session manager lets you get a shell on a private instance without ssh, a key pair or a public ip
- one instance can only be connected to one instance profile: to give it two separate permissions, you need a combined role and profile that contains both of them


### Network Traffic Flow Architecture

This document maps out the inbound and outbound network paths for web servers deployed in both private (proxied via ALB) and public (directly accessible) subnets within an AWS VPC environment.

> note: security groups are stateful, so the "outbound" paths below are responses to the inbound requests - they don't need their own outbound rules. traffic that the server starts itself (like package updates) is covered in section 3.

---

### 1. Private Subnet Routing (With ALB Proxy)

This architecture isolates the web application from direct internet exposure. The EC2 instance resides in a private subnet, while an Application Load Balancer (ALB) handles public-facing traffic.

#### Inbound Traffic Path
```text
[1. Public User Browser]
       │
       ▼ (Resolves the ALB DNS name)
[2. Internet Gateway]
       │
       ▼ (Funnels traffic into the VPC)
[3. Application Load Balancer (Public Subnets, 2 AZs)]
       │
       ▼ (Listener on port 80 forwards to the target group - allowed by app_sg, source alb_sg)
[4. EC2 Web Server (Private Subnet)]
```

#### Outbound Traffic Path (response)
```text
[1. User Browser]
       ▲
       │ (Delivers webpage across public internet)
[2. Internet Gateway]
       ▲
       │ (Passes the data out through the border)
[3. Application Load Balancer (ALB)]
       ▲
       │ (Sends response back over internal VPC lines)
[4. EC2 Web Server (Private Subnet)]
```

---

### 2. Public Subnet Routing (Direct Access)

This architecture places the web application directly in a public subnet, exposing the instance virtual network interface card (NIC) to the internet via a public IP address.

#### Inbound Traffic Path
```text
[1. Public User Browser]
       │
       ▼ (Hits Instance Raw Public IP)
[2. Internet Gateway]
       │
       ▼ (Routes directly to the instance virtual NIC)
[3. EC2 Web Server (Public Subnet)]
```

#### Outbound Traffic Path (response)
```text
[1. User Browser]
       ▲
       │ (Sends response out to public internet)
[2. Internet Gateway]
       ▲
       │ (Routes traffic out of the VPC border)
[3. EC2 Web Server (Public Subnet)]
```

---

### 3. Private Subnet Outbound Access (NAT Gateway)

Traffic that the private instance starts itself (package installs in user_data, SSM agent, S3 calls). The NAT gateway lets it out, but nothing on the internet can start a connection back in.

```text
[1. EC2 Web Server (Private Subnet)]
       │
       ▼ (Private route table: 0.0.0.0/0 -> NAT gateway)
[2. NAT Gateway (Public Subnet, Elastic IP)]
       │
       ▼ (Public route table: 0.0.0.0/0 -> internet gateway)
[3. Internet Gateway]
       │
       ▼
[4. Internet (dnf package repos, SSM / S3 endpoints)]
```
