### Network Traffic Flow Architecture

This document maps out the inbound and outbound network paths for web servers deployed in both private (proxied via ALB) and public (directly accessible) subnets within an AWS VPC environment.

---

### 1. Private Subnet Routing (With ALB Proxy)

This architecture isolates the web application from direct internet exposure. The EC2 instance resides in a private subnet, while an Application Load Balancer (ALB) handles public-facing traffic.

#### Inbound Traffic Path
```text
[1. Public User Browser]
       │
       ▼ (Resolves DNS / Hits Public IP)
[2. Internet Gateway]
       │
       ▼ (Funnels traffic into the VPC container)
[3. Application Load Balancer (Public Subnet)]
       │
       ▼ (Proxies request across internal VPC lines)
[4. EC2 Web Server (Private Subnet)]
```

#### Outbound Traffic Path
```text
[1. User Browser]
       ▲
       │ (Delivers webpage across public internet)
[2. Internet Gateway]
       ▲
       │ (Passes the data out through the border)
[3. Application Load Balancer (ALB)]
       ▲
       │ (Sends response back over internal VPC lines)
[4. EC2 Web Server (Private Subnet)]
```

---

## 2. Public Subnet Routing (Direct Access)

This architecture places the web application directly in a public subnet, exposing the instance virtual network interface card (NIC) to the internet via a public IP address.

#### Inbound Traffic Path
```text
[1. Public User Browser]
       │
       ▼ (Hits Instance Raw Public IP)
[2. Internet Gateway]
       │
       ▼ (Routes directly to the instance virtual NIC)
[3. EC2 Web Server (Public Subnet)]
```

#### Outbound Traffic Path
```text
[1. User Browser]
       ▲
       │ (Sends response out to public internet)
[2. Internet Gateway]
       ▲
       │ (Routes traffic out of the VPC border)
[3. EC2 Web Server (Public Subnet)]
```
